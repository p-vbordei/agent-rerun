## Stage 2.1 — Smallest vertical slice

The minimum that proves the design: **library-only, no signature, byte tolerance, end-to-end.** No CLI, no semantic, no signing. Just enough to capture a bundle from a step record, verify a matching actual record, and ship a passing test.

### Substages

#### 2.1.a — Project scaffold
- `package.json` (Apache-2.0, deps: `zod`, `@noble/hashes`, `@noble/ed25519`, `canonicalize`).
- `tsconfig.json` (strict).
- `biome.json` (one config, no lint war).
- `bunfig.toml` only if needed.
- `.gitignore` (node_modules, dist).
- **Verify:** `bun install` succeeds; `bun test` runs zero tests cleanly; `tsc --noEmit` passes.

#### 2.1.b — JCS bytes helper (`src/jcs.ts`)
- `jcsBytes(value: unknown): Uint8Array` — wraps `canonicalize` and returns UTF-8 bytes.
- **Verify:** unit test asserts `jcsBytes({ b: 1, a: 2 })` produces `{"a":2,"b":1}` bytes (key order canonicalized).

#### 2.1.c — SHA-256 helper (`src/hash.ts`)
- `sha256Hex(bytes: Uint8Array): string` returning `sha256:<hex>`.
- **Verify:** unit test against known SHA-256 vector (e.g. `sha256(JCS({})) == sha256:44136fa355b3678a1146ad16f7e8649e94fb4fc21fe77e8310c060f61caaff8a`).

#### 2.1.d — Zod schema for bundle and actual record (`src/schema.ts`)
- `Bundle`, `ActualRecord` Zod schemas matching SPEC §2 and §5.
- Required vs optional matches SPEC; conditional requirements (`byte` requires `transcript_sha256`, `semantic` requires `semantic_embedding` + `threshold`) enforced via `superRefine`.
- **Verify:** parse a hand-crafted valid bundle (no signature, byte tolerance); parse a fixture with conditional violation and assert it fails.

#### 2.1.e — `capture(stepRecord) → Bundle` (`src/capture.ts`)
- Computes the three input hashes from `stepRecord.inputs`.
- Builds the bundle JSON with `rerun_version`, model, sampling, runtime, expected, tolerance fields.
- No signature in this slice (deferred to 2.2.a).
- **Verify:** `capture(known step) == expected bundle JSON`.

#### 2.1.f — `verify(bundle, actual) → VerifyResult` (`src/verify.ts`)
- Schema validation.
- Recompute and compare each `inputs.*_sha256` field present in the bundle (C4-shaped check).
- Tolerance: `byte` only in this slice (compare `sha256(JCS(actual.output.transcript))` to `bundle.expected.transcript_sha256`).
- Returns `{ verified: boolean, errors: string[] }`.
- **Verify:** end-to-end test — `capture → verify(bundle, actual) === { verified: true }` on matching inputs; `verify(bundle, mutated_actual) === { verified: false, errors: [...] }` on mismatched messages.

#### 2.1.g — Public API (`src/index.ts`)
- Re-exports `capture`, `verify`, `Bundle`, `ActualRecord`, `VerifyResult`.
- **Verify:** import-and-use test from `tests/index.test.ts` exercises both functions through the public surface.

**Slice exit criteria:**
- All tests pass with `bun test`.
- `tsc --noEmit` clean.
- `biome check .` clean.
- `git status` clean after commit.
- The README's elevator-paragraph code example compiles and runs (sans `signingKey` which arrives in 2.2.a).

## Stage 2.2 — Remaining IN-V0.1 features

Each sub-stage adds one feature and ends with a passing test.

### 2.2.a — Ed25519 sign / verify
- `src/sign.ts`: `sign(bundle, privateKey)` and `verifySignature(bundle, publicKey?)`.
- Signature is over `JCS(bundle without "signature")`.
- `capture(stepRecord, { signingKey })` adds the signature block.
- `verify` checks the signature when present; mutated bytes invalidate.
- **Verify:** sign then verify a bundle round-trips; flipping one byte of any field after signing makes verify return `BadSignature`.

### 2.2.b — Semantic tolerance in verify
- `src/cosine.ts`: pure cosine over two `Float32Array`s; throws on dimension mismatch.
- Base64 ↔ Float32Array helpers (Bun's `Buffer.from(b64, 'base64')` over an `ArrayBuffer`).
- Extend `verify` to handle `tolerance.level === "semantic"`: decode both embeddings, cosine, compare to threshold.
- `verify` with `tolerance.level === "structural"` returns `{ verified: false, errors: ["structural tolerance not supported in v0.1"] }`.
- **Verify:** unit tests for cosine math (orthogonal → 0, identical → 1, threshold edge cases). End-to-end test: bundle with semantic tolerance + matching actual embedding passes; below-threshold cosine fails.

### 2.2.c — CLI: `rerun capture`
- `src/cli.ts`: argument parsing without a CLI framework (`Bun.argv`).
- `rerun capture <step.json> -o <bundle.rr> [--key <ed25519-private-key.json>]`.
- Reads JSON, calls `capture()`, writes JCS-canonical bundle bytes to output (so two captures of the same step produce byte-identical files).
- **Verify:** integration test that runs the CLI as a subprocess on a fixture step and diff-compares the output to a golden bundle.

### 2.2.d — CLI: `rerun verify`
- `rerun verify <bundle.rr> <actual.json>`.
- Exit code 0 on pass, 1 on fail. Prints per-rule verdict.
- **Verify:** integration test running the CLI on (a) a passing pair → exit 0; (b) a tampered bundle → exit 1 with "BadSignature" in stderr; (c) a mismatched messages actual → exit 1 with "InputHashMismatch" in stderr.

### 2.2.e — Single-binary build
- `package.json` `bin` field maps `rerun` to a built binary.
- Build script: `bun build --compile src/cli.ts --outfile dist/rerun`.
- **Verify:** post-build, run `./dist/rerun verify ...` from the integration tests instead of `bun src/cli.ts`. CI matrix runs both.

## Stage 2.3 — Conformance vectors

`conformance/` is standalone. `bun run conformance` runs every vector and exits 0 if all pass. Total run < 30 seconds.

Each vector is a directory with `bundle.rr`, `actual.json`, and `expected.json` describing the expected verify result.

### 2.3.a — C1: byte replay passes
- One signed bundle with `tolerance.level === "byte"`.
- Matching actual record.
- Expected: `{ verified: true }`.

### 2.3.b — C2: semantic replay passes
- One signed bundle with `tolerance.level === "semantic"`, `threshold === 0.95`, precomputed `expected.semantic_embedding`.
- Actual record with precomputed `output.embedding` whose cosine ≥ 0.95.
- Expected: `{ verified: true }`.
- Embeddings are checked-in fixtures (no live embedder).

### 2.3.c — C3: mutated bundle bytes rejected
- Same C1 bundle but with a single byte flipped after signing.
- Same matching actual record.
- Expected: `{ verified: false, errors: ["BadSignature"] }`.

### 2.3.d — C4: messages hash mismatch rejected
- Same C1 bundle.
- Actual record where one message is changed.
- Expected: `{ verified: false, errors: ["InputHashMismatch: messages_sha256"] }`.

### 2.3.e — Bonus vectors
- C2 below threshold: `cosine === 0.94, threshold === 0.95` → fail with `SemanticBelowThreshold`.
- Schema violation: required field missing → fail with `SchemaViolation`.
- Structural tolerance: `tolerance.level === "structural"` → fail with `UnsupportedTolerance`.
- Wrong embedder dimensions: 768-dim actual embedding vs 384-dim expected → fail with `EmbeddingDimensionMismatch`.

### 2.3.f — Conformance runner
- `conformance/run.ts` walks each vector dir, runs `verify`, compares against `expected.json`, exits 1 on any mismatch.
- **Verify:** `bun run conformance` exits 0; mutate any `bundle.rr` byte and the runner exits 1.

## Stage 2.4 — Security-consideration tests

One test per SPEC §6 bullet, where testable.

| SPEC §6 bullet | Test |
|---|---|
| Signatures are advisory | Documented in tests/security/signatures-advisory.md (no test — definitional). |
| Fingerprint drift | `verify` with mismatched `model.fingerprint` and `tolerance: semantic` returns `{ verified: true, warnings: ["FingerprintDrift"] }`. |
| Tamper detection | Covered by C3 + an additional test that mutates `expected.transcript_sha256` post-signature → BadSignature. |
| Determinism best-effort | Documented in tests/security/determinism.md (no test — boundary statement). |
| Privacy: bundles store hashes only | `tests/security/privacy.test.ts` greps a captured bundle for the plaintext input strings; asserts none are present. |

## Risks and mitigations

| Risk | Mitigation |
|---|---|
| `canonicalize` package returns a string (not bytes), with platform-specific newline handling. | `src/jcs.ts` wraps and explicitly UTF-8 encodes. Test on a fixture with non-ASCII content. |
| Bun's `Buffer.from(base64)` returns a `Buffer` (Node compat); we want raw `Float32Array`. | Convert via `new Float32Array(buf.buffer, buf.byteOffset, buf.byteLength / 4)`. Document the little-endian assumption. |
| `bun build --compile` cross-platform issues. | Build only the host platform in CI v0.1; cross-compile is v0.2 if asked. |
| Conformance vectors need precomputed embeddings. | Generate once with a checked-in script (`scripts/gen-embeddings.ts`) using `@huggingface/transformers` as a dev-dep; freeze the outputs into `conformance/`. |
